# 📖 我的小说书库 (Novel H5 Web App)

> 一个基于 **GitHub Pages** 托管的纯静态、高性能、响应式网络小说 H5 阅读器与文本托管工具。  
> 专为碎片化阅读、快速复制切片文本设计，支持多设备云端进度同步、抽屉式弹窗滚动阅读及全自动化发布。

---

## ✨ 核心特性

- 📱 **移动端优先与极速体验**：纯静态前端单页架构（HTML5 + CSS3 + 原生 ES6），无任何重量级框架依赖，秒级加载。
- 📋 **切片复制与已读追踪**：
  - 点击“复制”一键将章节切片全文写入剪贴板，并自动标记为已读。
  - 支持在通知浮层（Toast）中一键“撤销已读”，或直接点击已读按钮恢复未读。
- 📖 **优雅的抽屉阅读弹窗**：
  - 每个章节条目均支持点击【查看】打开底部抽屉弹窗。
  - 段落排版舒适，支持内部自由顺畅滚动阅读；提供弹窗内一键复制。
  - 支持左上角关闭、点击背景遮罩、键盘 `ESC` 键多维快速退出。
- 🏷️ **智能筛选与状态记忆**：
  - 默认进入小说时优先展示**【未读】**条目，跳过已读章节，直奔最新阅读进度。
  - 支持“全部 / 未读 / 已读”即时分类无刷新筛选。
- ☁️ **GitHub Gist 跨设备双向同步**：
  - 支持绑定个人的 GitHub Token，自动创建并托管私有 Gist。
  - 基于时间戳裁决（Last-Write-Wins），换设备时自动拉取最新进度，撤销操作也能完美同步。
- 🌓 **深色模式适配**：全局 CSS 变量与主题切换，深色模式下杜绝滚动露白。

## 🛠️ 如何手动更新小说

如果你在本地编写、下载或整理了新的小说章节，可以通过以下步骤手动更新书库：

### 1. 为已有小说追加新章节
1. 打开对应小说的目录（例如 `凡人修仙传/` 或 `逆天邪神/`）。
2. 将新的切片 txt 文件直接拖入该目录中（例如追加 `101-110 章.txt`, `111-120 章.txt`）。
3. 在项目根目录下打开终端，运行索引生成脚本：
   ```bash
   python3 generate_index.py
   ```
4. 脚本会自动重新扫描目录、按自然数字排序、提取首行摘要并更新 `books.json`。

### 2. 上架全新小说
1. **新建小说目录**：在项目根目录下新建一个以小说名命名的文件夹（例如 `斗破苍穹/`）。
2. **放入文件**：
   - **封面图片**：命名为 `封面.jpeg`（或 `封面.jpg`、`封面.png`）。
   - **章节切片**：按命名规范放置 `1-10 章.txt`, `11-20 章.txt` 等。
3. **配置小说分类与简介（推荐）**：
   - 打开 [`generate_index.py`](generate_index.py)，在顶部的 `BOOK_META` 中添加该小说自定义的分类（`category`）和简介（`description`）：
     ```python
     BOOK_META = {
         "凡人修仙传": {
             "category": "仙侠",
             "description": "一个普通的山村少年，机缘巧合之下踏入修仙之路。"
         },
         "逆天邪神": {
             "category": "玄幻",
             "description": "掌天毒之珠，承邪神之血，修逆天之力，逆天而行。"
         },
         # 新增的小说：
         "斗破苍穹": {
             "category": "玄幻",
             "description": "这里是属于斗气的世界，没有花俏艳丽的魔法，有的，仅仅是繁衍到巅峰的斗气！"
         }
     }
     ```
   - *注：如果未在 `BOOK_META` 中配置，脚本会自动使用默认兜底值（分类为“网络小说”，简介为“《书名》精彩章节持续收录。”）。*
4. **运行索引生成脚本**：
   ```bash
   python3 generate_index.py
   ```
   脚本会自动把书名、封面、切片章节、以及你在 `BOOK_META` 里配置的分类与简介统一打包写入 `books.json`。

### 3. 本地预览与测试
在项目根目录启动本地简易 HTTP 服务进行验证：
```bash
python3 -m http.server 8088
```
用浏览器访问 `http://localhost:8088/index.html`，确认新小说和章节渲染无误。

### 4. 提交推送到 GitHub
确认无误后，将改动提交并推送到远端：
```bash
git add .
git commit -m "feat: 更新小说章节"
git push origin main
```
推送成功后，GitHub Pages 会在 1~2 分钟内完成部署，在线页面即可查看到最新内容。

## ⚠️ 注意事项与规范

为了确保自动化脚本和网页端能够稳定解析与排版，请务必遵守以下规范：

### 1. 章节切片命名规范（极重要）
- **推荐命名**：`X-Y 章.txt`（如 `1-10 章.txt`、`101-110 章.txt`）。
- **排序原理**：脚本内置了正则表达式数字范围解析与**自然数排序**算法。如果不包含数字范围，可能会导致 `10-20` 排在 `2-10` 前面的字符字典序问题。
- 请勿在文件名中使用特殊字符（如 `/`、`\`、`?`、`*`、`:` 等）。

### 2. 文件编码规范
- 所有 `.txt` 章节文本必须保存为 **`UTF-8`** 编码。
- 若使用了 Windows 默认的 `GBK` / `ANSI` 编码保存，可能会导致文字解析出现乱码。

### 3. 章节摘要提取机制
- 脚本会自动读取每个 txt 文件的**第一行非空文字**，并严格提取**前 10 个有效非空白字符**作为条目摘要。
- 建议每个切片文本的首行保留章节标题（例如：`第1章 初入江湖...`），这样可以在列表卡片上获得最佳的预览效果。

### 4. 静态资源缓存说明
- 前端已在 `fetch('books.json?t=...')` 中加入了时间戳防静态缓存机制，确保只要线上 `books.json` 发生更新，用户刷新页面即可立即看到最新章节。
- 但由于 GitHub Pages CDN 分发存在轻微延迟，推送后若未立即生效，请等待 1~2 分钟后刷新页面。

## 🤖 已配置的自动化发布流程 (CI/CD)

为了让你无需每次都在本地手动运行 Python 脚本和生成索引，本项目已深度集成了 **GitHub Actions 自动构建工作流**。

### 1. 配置文件路径
- [`.github/workflows/update-index.yml`](.github/workflows/update-index.yml)

### 2. 触发条件 (Trigger)
每当你通过任何途径（无论是本地 `git push`、GitHub Web 网页端直接上传，还是第三方同步工具）向 `main` 分支推送以下内容时，工作流会自动触发：
- 任何小说目录下的 `.txt` 章节文件（`**/*.txt`）
- 任何封面图片（`**/封面.*`）
- 索引生成脚本本身（`generate_index.py`）

### 3. 自动化执行逻辑
1. **环境检出**：GitHub Actions Runner 自动拉取最新的代码仓库。
2. **执行索引生成**：自动安装 Python 3 环境，并执行 `python3 generate_index.py`。
3. **智能差异比对**：
   - 如果新切片导致了 `books.json` 变动，工作流会自动以 `github-actions[bot]` 的身份创建提交：
     ```text
     chore: 自动同步更新小说章节索引 [skip ci]
     ```
   - 自动推回 `main` 分支。
   - `[skip ci]` 标识能有效防止提交引发死循环触发。
4. **全自动闭环体验**：
   > **这意味着你完全可以在 GitHub 网页端直接上传新章节文件，什么命令都不用敲，Actions 会在后台自动完成索引构建和发布！**

## 📱 GitHub Gist 多设备同步配置（可选）

如果你在手机、iPad、电脑等多台设备之间切换阅读，并希望已读/未读进度完全一致：

1. 登录 GitHub，访问 [Personal Access Tokens (Classic)](https://github.com/settings/tokens)。
2. 点击 **Generate new token (classic)**，Note 填写 `Novel Sync`，在权限列表中**仅勾选 `gist`** 权限，点击生成。
3. 复制生成的 Token（形如 `ghp_xxxx`）。
4. 在本阅读器 H5 中点击底部 **【设置】** -> **GitHub 云端同步** -> 粘贴 Token -> 点击 **【连接并同步进度】**。
5. 系统会自动在你的 GitHub 账号下创建并托管私有的 `novel_read_status.json` Gist，并在每次标记或撤销已读时自动静默双向同步！
